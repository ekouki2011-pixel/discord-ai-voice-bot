# 開発・構造

## モジュール

|場所|役割|
|---|---|
|`src/discord/commands.ts`|スラッシュコマンド定義、管理コマンド既定権限|
|`src/discord/handlers.ts`|操作受付、実行時の権限確認、指定チャンネルの自動読み上げ|
|`src/discord/voice.ts`|DAVE有効のVC接続、再接続待ち、FFmpeg、再生、一時音声削除、無人退出|
|`src/service.ts`|個人・既定設定の解決、利用許可・予算確認、明示同意のある代替|
|`src/queue.ts`|サーバー別FIFO、生成・再生キャンセル、全体合成数制限|
|`src/engines/`|独立した4サービスとHTTP制御|
|`src/db.ts`|SQLite WAL、設定・許可・キャッシュ・使用量、オンラインバックアップ|
|`src/text.ts`|文字数判定、URL・メンション・絵文字・伏せ字の整形、連投制限|
|`src/index.ts`|Discordイベント、最小Intent、ヘルスチェック、終了処理|

音声の受信順を保つため、合成前に待機枠を確保します。受信した本文はRAMだけに置き、先頭の仕事を合成・再生します。同時合成を複数開始してから終了順に並べる設計にはしません。待機列上限には生成・再生中も含みます。

エンジンの追加は `Engine` インターフェースを実装し、`Engines` に登録します。速度・高さの対応範囲を公開し、サービス層で検証します。未対応の操作を無言で反映したことにしません。HTTPタイムアウト、音声サイズ上限、JSONエラー、再試行の可否は共通処理です。

## 保存データ

サーバーIDごとの設定と、サーバーID＋ユーザーIDごとの個人設定を分離します。個人設定を作成すると、その時点の有効設定一式を保存します。サーバー既定を後から変更しても、既存の個人設定を上書きしません。`/profile reset` で既定へ戻せます。各個人設定に更新日時を保存します。

音声一覧は運用者のAPIアカウント単位で共有キャッシュを持ち、利用許可はサーバー別です。一般ユーザーには許可済み音声だけ表示します。同期で一覧から消えた声は生成前の確認で利用不可になります。承認の有無にかかわらず、未同期・処理中・失敗状態の音声は生成しません。古いキャッシュの状態は実際のサービス状態を保証しないため、APIエラーも処理します。

使用量の確認と加算はSQLiteの単一トランザクションで行います。グローバル上限を超えた場合、サーバー・個人の加算もロールバックします。同一DBを複数Botプロセスから使う構成や、Botの水平分散には対応しません。1トークン・1プロセスで運用します。

## 制限と実装上の選択

- 通常テキストチャンネル、通常VCを対象にします。スレッド・ステージVCは対象外です。
- 自動読み上げの投稿者はBotと同じVCにいる必要があります。生成前と再生直前に参加・権限を確認します。
- 同じVCの参加者はskip/stop/leaveを使用できます。管理者は停止・退出を代行できます。
- Botを別VCへ外部から移動した場合は接続を破棄して待機列を止めます。意図しないVCへ本文を流しません。
- 無人になった時点で待機列を止め、指定時間後に退出します。再起動後の自動VC復帰は行わず `/join` を要求します。
- 一時停止、音声利用許可解除、対象チャンネル変更時は既存の待機列も削除します。
- 外部APIからのレスポンス本文・例外オブジェクトをログに出しません。ユーザー向けエラーは既知の分類で表示します。
- SaydiVoiceのGET音声取得とPOST音声生成だけを実装し、作成・変更・削除APIは呼びません。レスポンスが異なる声への置換を報告した場合は再生を拒否します。

## 開発コマンド

`npm run check` は型チェック、Lint、自動テスト、ビルドを順に実行します。HTTPのモック、実SQLite、ローカルHTTPサーバー、実FFmpeg／Opus変換を分けて検証します。テストでAPIキーは不要です。自動テストは実Discordや有料音声APIへ接続しません。

`npm run smoke:voicevox` は起動中の実VOICEVOXへ接続する別の試験です。事前に話者の条件を確認し、`VOICEVOX_TEST_STYLE_ID` と `ENGINE_TERMS_ACCEPTED=voicevox` を設定してください。生成された日本語音声をFFmpegでデコードして検証します。Discordへの送信は行いません。
